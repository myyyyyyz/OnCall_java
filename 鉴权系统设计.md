## 1. 需求概述

### 1.1 核心需求

| 需求 | 说明 | 优先级 |
|------|------|--------|
| **风险低的操作自动鉴权** | 常规查询、健康检查等接口自动通过鉴权 | P0 |
| **敏感操作增加确认环节** | 删除、配置修改等高风险操作需二次确认 | P0 |
| **多层鉴权** | Token 鉴权 → 角色鉴权 → 操作鉴权 | P0 |
| **日志详细记录** | 记录所有鉴权相关操作，支持审计追溯 | P0 |

### 1.2 风险等级定义

| 等级 | 操作类型 | 示例接口 | 鉴权策略 |
|------|----------|----------|----------|
| **低风险** | 查询、健康检查 | `/api/chat/*`, `/milvus/health` | 自动鉴权，仅需有效 Token |
| **中风险** | 数据写入、文件上传 | `/api/upload` | Token + 角色验证 |
| **高风险** | 删除、配置修改、清空操作 | `/api/chat/clear`, `/api/config/*` | Token + 角色 + 二次确认 |

### 3.3 多层鉴权设计

#### Level 1: Token 有效性验证（自动）

```
┌─────────────────────────────────────────────────────────────┐
│                    JwtAuthenticationFilter                  │
├─────────────────────────────────────────────────────────────┤
│  1. 检查 Authorization Header 是否存在                        │
│  2. 验证 JWT Token 签名有效性                                 │
│  3. 检查 Token 是否过期                                       │
│  4. 检查 Token 是否在黑名单中 (Redis)                          │
│  5. 提取用户信息并设置到 SecurityContext                     │
└─────────────────────────────────────────────────────────────┘
```

**放行规则**:
- 公开接口：`/api/auth/*`, `/api/public/*`
- 健康检查：`/milvus/health`, `/actuator/health`

#### Level 2: 角色权限验证（自动）

```
┌─────────────────────────────────────────────────────────────┐
│                  @PreAuthorize 注解                          │
├─────────────────────────────────────────────────────────────┤
│  @PreAuthorize("hasRole('ADMIN')")                          │
│  @PreAuthorize("hasAnyRole('ADMIN', 'OPERATOR')")           │
│  @PreAuthorize("@securityChecker.canAccess(#resource)")     │
└─────────────────────────────────────────────────────────────┘
```

**角色定义**:
| 角色 | 权限范围 |
|------|----------|
| `ROLE_ADMIN` | 全部权限，包括配置修改、数据删除 |
| `ROLE_OPERATOR` | 常规操作，包括文件上传、对话查询 |
| `ROLE_USER` | 基础查询，仅对话接口 |

#### Level 3: 操作确认（高风险操作）

```
┌─────────────────────────────────────────────────────────────┐
│              @RequireConfirmation 自定义注解                 │
├─────────────────────────────────────────────────────────────┤
│  1. 检测请求是否包含 confirmationCode                        │
│  2. 验证 confirmationCode 是否有效 (Redis 缓存，5 分钟有效期)   │
│  3. 验证通过后执行操作，并清除 confirmationCode              │
│  4. 失败则返回 403 + 确认提示                                │
└─────────────────────────────────────────────────────────────┘
```

**高风险操作列表**:
- `/api/chat/clear` - 清空会话历史
- `/api/config/*` - 配置修改
- `/api/user/delete/**` - 用户删除
- `/api/vector/drop` - 向量库清空


### 3.5 审计日志设计

```
┌─────────────────────────────────────────────────────────────┐
│                    SecurityLogEntity                        │
├─────────────────────────────────────────────────────────────┤
│  - id: Long                     # 日志 ID                    │
│  - userId: Long                 # 操作用户 ID                 │
│  - username: String             # 操作用户名                 │
│  - action: String               # 操作类型 (LOGIN/UPLOAD/...)│
│  - resource: String             # 操作资源 (URL/文件路径)     │
│  - riskLevel: RiskLevel         # 风险等级                  │
│  - result: String               # 操作结果 (SUCCESS/FAIL)   │
│  - ipAddress: String            # 请求 IP                   │
│  - userAgent: String            # 客户端信息                 │
│  - requestParams: String        # 请求参数 (JSON)           │
│  - errorMessage: String         # 错误信息 (如有)           │
│  - timestamp: LocalDateTime     # 操作时间                  │
└─────────────────────────────────────────────────────────────┘
```

**日志记录策略**:
- 所有鉴权相关操作必须记录
- 高风险操作记录完整请求参数
- 失败操作记录详细错误信息
- 支持异步写入，不影响主流程性能

## 6. 接口设计

### 6.1 认证接口

#### 6.1.1 用户登录

```http
POST /api/auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "password123"
}

# 响应
{
  "code": 200,
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "expiresIn": 900,           // Access Token 有效期 (秒)
    "tokenType": "Bearer",
    "user": {
      "id": 1,
      "username": "admin",
      "roles": ["ROLE_ADMIN"]
    }
  }
}
```

#### 6.1.2 刷新 Token

```http
POST /api/auth/refresh
Content-Type: application/json

{
  "refreshToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

# 响应
{
  "code": 200,
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "expiresIn": 900,
    "tokenType": "Bearer"
  }
}
```

#### 6.1.3 用户登出

```http
POST /api/auth/logout
Authorization: Bearer {accessToken}

# 响应
{
  "code": 200,
  "message": "登出成功"
}
```

### 6.2 二次确认接口

#### 6.2.1 发起确认请求

```http
POST /api/confirmation/request
Authorization: Bearer {accessToken}
Content-Type: application/json

{
  "operation": "DELETE",
  "resource": "/api/chat/clear",
  "reason": "清空会话历史将删除所有对话记录，是否继续？"
}

# 响应
{
  "code": 200,
  "data": {
    "confirmationCode": "CONF-20260317-ABC123",
    "expiresIn": 300,  // 确认码 5 分钟有效
    "message": "请在 5 分钟内使用确认码完成操作"
  }
}
```

#### 6.2.2 验证确认码

```http
POST /api/confirmation/verify
Authorization: Bearer {accessToken}
Content-Type: application/json

{
  "confirmationCode": "CONF-20260317-ABC123"
}

# 响应
{
  "code": 200,
  "data": {
    "valid": true,
    "operation": "DELETE",
    "resource": "/api/chat/clear"
  }
}
```

## 7. 数据库设计

### 7.1 用户表 (users)

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,      -- BCrypt 加密
    email VARCHAR(100),
    phone VARCHAR(20),
    enabled BOOLEAN DEFAULT TRUE,
    account_non_expired BOOLEAN DEFAULT TRUE,
    account_non_locked BOOLEAN DEFAULT TRUE,
    credentials_non_expired BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    last_login_at TIMESTAMP NULL,
    last_login_ip VARCHAR(50)
);
```

### 7.2 角色表 (roles)

```sql
CREATE TABLE roles (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL UNIQUE,     -- ROLE_ADMIN, ROLE_USER, etc.
    description VARCHAR(255),
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

### 7.3 用户角色关联表 (user_roles)

```sql
CREATE TABLE user_roles (
    user_id BIGINT NOT NULL,
    role_id BIGINT NOT NULL,
    PRIMARY KEY (user_id, role_id),
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
    FOREIGN KEY (role_id) REFERENCES roles(id) ON DELETE CASCADE
);
```

### 7.4 安全日志表 (security_logs)

```sql
CREATE TABLE security_logs (
```

## 10. 安全建议

### 10.1 生产环境建议

1. **JWT 密钥**: 使用环境变量或配置中心，不要硬编码
2. **HTTPS**: 生产环境必须启用 HTTPS
3. **密码策略**: 强制密码复杂度要求 (长度、大小写、特殊字符)
4. **限流**: 登录接口增加限流保护 (如 5 次/分钟)
5. **账户锁定**: 连续失败多次后锁定账户
6. **日志审计**: 定期审查安全日志，发现异常行为
7. **Token 黑名单**: 登出时将 Token 加入黑名单 (Redis)

### 11.1 风险等级判定规则

```java
/**
 * 风险等级判定规则
 */
public class RiskLevelRules {
    
    // 规则 1: HTTP 方法
    DELETE, PUT → 风险 +1
    POST → 风险 +0
    GET → 风险 -1
    
    // 规则 2: URL 路径
    包含 /delete/, /clear/, /drop/ → 风险 +2
    包含 /config/, /setting/ → 风险 +1
    包含 /upload/, /import/ → 风险 +1
    
    // 规则 3: 用户角色
    ROLE_USER → 风险 +1
    ROLE_OPERATOR → 风险 +0
    ROLE_ADMIN → 风险 -1
    
    // 最终判定
    风险值 <= 0 → LOW
    风险值 == 1 → MEDIUM
    风险值 >= 2 → HIGH
}
```

```java
/**
 * 确认码格式: CONF-YYYYMMDD-XXXXXX
 * 示例: CONF-20260317-ABC123
 */
public String generateCode() {
    String date = LocalDate.now().format(DateTimeFormatter.BASIC_ISO_DATE);
    String random = RandomStringUtils.randomAlphanumeric(6).toUpperCase();
    return String.format("CONF-%s-%s", date, random);
}
```
